Brand & Interface Guide

Warm Ledger / Record Clasp / version1.0 / 13 October2026

Brand premise

MatchDocket makes invoice exception review tangible: a record, its evidence and an accountable human decision. Warm Ledger is the selected website direction; Record Clasp is the selected symbol from logo round two. This kit is a design system and synthetic preview reference, not an operating financial product.

Character: assured, warm, precise, considered and accountable. Prefer specific sources and clear limits over AI slogans. The logo stays simple; illustrations carry tactile editorial detail.

Identity assets

The mark is a canonical vector redraw of the approved Record Clasp study, normalized across all versions. The wordmark is outlined Newsreader at weight 500 and optical size 48. It is a licensed type treatment, not a claim of a proprietary custom typeface.

  • Horizontal logo, wordmark alone, mark alone and favicon in olive, ivory, black and white.
  • Clear space: half the mark width on all sides. Minimum proposed horizontal width: 140px; use the mark below that size.
  • Never stretch, rotate, outline, emboss, add a shadow or fill the mark with a photo. Keep it off busy illustration detail.
  • Use the SVG logo in the navbar; use icon-only 16/32px favicon variants and larger touch/app icon renders.
  • Original exploratory logo sheets are retained separately. Trademark clearance is outside this kit.

Voice: plain, concrete and bounded. “Inspect the evidence” is better than a broad automation promise. “Proposal reviewed” is different from “payment approved.” Every concept preview retains its stage label.

Grid spacing alignment and elevation

  • 4px base spacing scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 120, 144.
  • Content cap 1280px; reading cap 640px; 12 desktop / 8 tablet / 4 mobile columns.
  • Page gutters: desktop 48px, tablet 32px, mobile 20px. Grid gap 24px.
  • Section spacing: 96px desktop, 64px mobile. Cards 24px; dense rows 52px; touch controls at least 44px.
  • Shared left edge for kicker, title, copy and action. Align data to baselines rather than centering arbitrary card contents.
  • Radius: 8px controls, 12px cards, 16px panels; pills only for a deliberate tag or CTA variant.
  • Shadow levels: paper 0/2/6 at 4%; floating 0/10/28 at 9%; evidence 0/20/48 at 12%. Tables rely on rules instead of floating shadows.

Components and interaction states

The reference includes primary, secondary, ghost, danger/hold, icon-only and disabled buttons; text-flip, arrow nudge, rising-fill and inset-border button effects; statuses; fields; error hints; consent checkbox; select controls; search; tabs; native disclosure tables; notices; empty states; toast feedback; navigation and a footer specimen.

  • Primary CTA: Request an exception audit. Secondary: Explore fictional demo. Carry the selected offer ID into operational intake later.
  • Default → hover → focus → pressed → loading → disabled → error → success are distinct states. A server-confirmed receipt is required before a real form says submitted.
  • A loading control retains its label and width, sets aria-busy=true, and prevents duplicate submission. A read-only evidence view uses a lock label, not just gray color.
  • Use 44px minimum button height and visible 3px terracotta focus. Icons need an accessible name when alone.
  • Consent is purpose-limited and never preselected. No invoice, tax, bank or credential upload in public intake.
  • The native proposal/override dialog traps focus, restores it on close and allows Escape. It shows the proposed diff or a synthetic reason field. It is a component specimen, not a live approval service.
  • Preview sign-in does not collect real passwords, simulate SSO or claim a successful identity check.

Motion language

Motion emphasizes source relationships, an optional explanation or an action affordance. It never silently approves a recommendation, marks a vendor verified or advances a financial state. No scroll-jacking, indefinite decorative animation or hidden source facts.

Icons and social footer

Lucide functional icons use a 24px source grid and a consistent 1.75–2px apparent stroke. Use 20px at normal controls, 16px beside dense metadata and 24–28px for section affordances. Status glyphs sit with labels. Brand marks remain separate from the functional icon vocabulary.

LinkedIn and Crunchbase SVGs are bundled for the footer. They are sourced brand marks, not endorsements or evidence of existing company profiles. Actual profile URLs are unset. Brand marks may carry trademark restrictions independent of the source asset license. Do not fake a client logo strip or security badge.

Footer anatomy: original logo and tagline, all five product directions, buyer/use cases, resources, company, controls/privacy/terms/accessibility, and operational contact. Add only verified addresses and real profile links.

Illustration language

Three original transparent raster masters are included: evidence folio, human-review folio and receiving records. Use deliberate crops and differing compositions across the website. Graphite outlines, sparse crosshatching, cream/sage washes, brass and small terracotta annotation establish material character.

  • Never bake monetary values, product claims, source IDs or action controls into the illustration. Live HTML/SVG owns exact labels.
  • Use texture in illustration objects, not over body text or inside the logo.
  • Avoid generic cash, coins, piggy banks, shield art, glow, AI orbs or decorative growth charts.
  • Maintain natural aspect ratios. Use object-fit:contain when the whole evidence object matters.
  • The receiving illustration is an atmospheric context asset; its physical part count is not an encoded quantity for GR-09.

Chart and figure system

Twenty families are implemented: status donut, module pie, amount bars, age columns, queue line/area, variance waterfall, three-way comparison, module lollipop, owner matrix, sparkline, packet subset, case-age dots, workflow, approvals, lineage, duplicate candidates, bank-change hold, proposed diff and packet anatomy.

Plain HTML owns labels, controls and tables. D3 owns scales/arcs/paths; simple schematic SVG carries explicit node relationships. Around 44 small SVG specimens coexist in this reference including hero and motion miniatures; there are no animation loops. On resize the main charts recompute from measured containers. A future site should load only the figures visible on its current route.

Responsive accessibility and implementation

  • Test 1440×900 desktop and390×844 mobile, plus tablet and200% zoom. Use native scrolling.
  • At mobile widths, stack source evidence before review; use named tabs instead of shrinking three desktop panes.
  • Touch users see visual information immediately; flips use explicit buttons. Respect prefers-reduced-motion and provide the preview toggle.
  • All controls have names, focus, validation/error text and appropriate disabled/expanded states. Tabs support arrows/Home/End; disclosures are native.
  • Numerical labels stay visible. Charts have title/desc and text/data tables. Status never relies on color alone.
  • Form specimen validates locally and explicitly reports nothing was submitted; do not enter sensitive data.
  • Use real operational privacy/counsel/security copy before enabling collection or publication. Do not add unsupported integrations, certifications, customer testimonials, savings or live telemetry.
